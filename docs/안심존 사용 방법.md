PDF 기준으로 보면, 안심존은 데이터를 내려받아 회사 PC에서 쓰는 구조가 아니라, 안심존 내부의 서버에 들어가서 데이터를 분석·학습하고 최종적으로 허용된 ‘소스코드 + 학습된 AI 모델’만 밖으로 반출하는 구조라고 이해하면 됩니다. 전체 흐름도도 데이터 선택 → 이용 신청 → 승인/자원 할당 → 안심존 접속 → 데이터 분석·연구 → 학습 모델 반출 순서로 되어 있습니다.

1. 먼저 ‘데이터 열람’이 아니라 ‘데이터 사용’을 신청해야 합니다

PDF에는 두 가지가 구분되어 있습니다. 단순히 데이터를 확인하고 탐색하는 데이터 열람 신청과, AI 모델 개발·심층 분석을 위한 데이터 사용 신청입니다. 모델을 만들려는 목적이면 후자인 데이터 사용 신청으로 가야 합니다.

데이터 사용 신청의 경우 IRB 심의가 필수이고, 연구계획서에 안심존 데이터 활용 내용과 정확한 데이터셋 명칭을 적어야 합니다. 또한 실제 안심존을 사용할 사람은 IRB 연구계획서에 연구자로 등록되어 있어야 합니다. 기본적으로 IRB 승인 연구 1건당 서버 1대를 지급하는 구조입니다.

즉 실무적으로는 다음 구조가 됩니다.

AI Hub에서 필요한 헬스케어 데이터 검색 → 데이터셋 결정 → 그 데이터셋을 사용하는 연구계획 작성 → IRB 승인 → 안심존 데이터 사용 신청

여러 데이터셋을 동시에 조합해서 학습할 생각이라면 처음 신청할 때 멀티데이터 신청을 해야 합니다. A 데이터와 B 데이터를 각각 별도로 신청하되 같은 시점에 신청해야 하고, 신청이 진행된 다음에 데이터셋을 추가할 수는 없습니다.

2. 신청하기 전에 ‘모델을 어떻게 만들지’를 거의 다 준비해 두는 게 중요합니다

여기가 꽤 중요합니다.

PDF상 GPU 서버 사용기간은 30일이고, 이 기간에는 주말과 공휴일도 포함됩니다. 사용 종료 후에는 바로 다시 신청할 수 있는 게 아니라, 초회 사용 종료일 기준 30일 뒤에 재신청할 수 있습니다. GPU 활용률이 너무 낮으면 자원이 조기 회수될 수도 있습니다.

그래서 안심존에 들어가서부터 "뭘 분석하지?", "어떤 모델을 써볼까?"를 고민하면 상당히 비효율적입니다.

제가 권하는 방식은 외부에서 가상 데이터 또는 동일 스키마 샘플 데이터로 학습 코드를 완성한 다음 안심존에 들어가는 것입니다.

예를 들어 밖에서 미리 아래 구조를 만들어 둡니다.

project/
├─ src/
│  ├─ preprocess.py
│  ├─ feature_engineering.py
│  ├─ train.py
│  ├─ evaluate.py
│  └─ explain.py
├─ configs/
│  └─ config.yaml
├─ requirements.txt
├─ notebooks/
│  └─ analysis.ipynb
└─ outputs/
   ├─ models/
   └─ metrics/

그리고 train.py를 실행하면 데이터 경로만 변경해서 안심존 데이터로 바로 학습되도록 만들어 놓는 게 좋습니다.

3. 안심존에 들어가면 처음에는 인터넷을 사용할 수 있습니다

안심존은 처음부터 무조건 인터넷이 차단된 것은 아닙니다.

매뉴얼에서는 실사용 전에 최대 5일간 외부망 연결 기간을 제공한다고 되어 있습니다. 이 기간 동안 필요한 프로그램·Python 패키지·자체 보유 데이터 등을 업로드하고 환경을 구성해야 합니다. 이후 안심존 데이터를 마운트하면 외부망이 차단됩니다.

따라서 아주 중요한 순서는 다음과 같습니다.

① 서버 받음
→ ② 인터넷이 되는 상태에서 개발환경 세팅
→ ③ 필요한 Python 패키지 설치
→ ④ 내가 만든 학습 코드 업로드
→ ⑤ 필요하다면 자체 보유 데이터 업로드
→ ⑥ 모든 것이 정상 실행되는지 테스트
→ ⑦ 데이터 마운트 요청
→ ⑧ 인터넷 차단
→ ⑨ 실제 안심존 데이터로 분석/학습

이 순서를 거꾸로 하면 굉장히 귀찮아질 수 있습니다.

데이터 마운트 후 외부 인터넷을 다시 써야 한다면 서버 초기화가 필요하고, 다시 환경 구축 → 데이터 마운트 과정을 거쳐야 합니다. 초기화에는 평일 기준 약 하루가 걸릴 수 있습니다.

4. 실제 서버 성능은 모델 개발하기에 꽤 괜찮습니다

매뉴얼에 기재된 GPU 서버 기본 환경은 다음과 같습니다.

CPU: 8 vCPU
RAM: 90GB
GPU: NVIDIA V100 32GB
SSD: 50GB + 작업용 500GB
Ubuntu 22.04
CUDA 12.2
Python 3.11
TensorFlow 2.16.1
PyTorch, Keras, Gensim 등 제공
Conda 및 Jupyter Notebook 제공

그래서 일반적인 의료 데이터의 XGBoost / LightGBM / Random Forest / Logistic Regression뿐 아니라 딥러닝까지 충분히 가능합니다.

다만 PDF에 나오는 Docker 이미지에 따라 Python·CUDA·PyTorch 버전이 달라지므로 내가 만든 코드와 호환되는 Docker 이미지를 신청 단계에서 선택하는 것이 중요합니다. 매뉴얼에서도 Python과 Notebook 버전 확인을 별도로 강조하고 있습니다.

5. 실제 데이터는 이런 식으로 사용하면 됩니다

안심존 데이터가 마운트되고 나면 원본 데이터 디렉터리가 생깁니다.

중요한 특징은 원본 데이터 폴더가 Read Only라는 것입니다. 원본을 직접 수정하면서 작업하는 게 아니라, 필요한 데이터를 사용자 작업폴더인 nasw로 복사해서 분석하도록 되어 있습니다.

즉 대략 이런 개념입니다.

안심존 원본 데이터
      │
      │ Read Only
      ↓
dataset/
      │
      │ 필요한 데이터 복사/읽기
      ↓
nasw/
├─ project/
├─ processed/
├─ models/
└─ download/

실무적으로는 원본 전체를 함부로 변형하지 말고,

원본 → 전처리 → 가공 데이터 → Train/Validation/Test → 모델

구조로 관리하는 게 좋습니다.

6. 모델 개발은 안심존 내부에서 이렇게 진행하는 게 가장 좋습니다

이 부분은 PDF가 모델링 방법 자체를 설명하는 것은 아니기 때문에, 아래는 제가 권하는 실제 ML 개발 방식입니다.

7. SHAP도 여기서 돌리는 게 좋습니다

안심존 데이터 자체를 밖으로 가져갈 수 없기 때문에 SHAP 같은 설명가능성 분석도 안심존 내부에서 수행하는 것이 자연스럽습니다.

예를 들어:

Model
  ↓
SHAP
  ├─ Global Feature Importance
  ├─ Beeswarm
  ├─ Dependence
  ├─ Interaction
  └─ Individual Prediction Explanation

다만 여기서 중요한 문제가 하나 있습니다.

SHAP 이미지 등을 마음대로 밖으로 반출할 수 있는 것은 아닙니다.

매뉴얼의 반출 규정이 상당히 엄격합니다.

8. 가장 중요한 부분: 데이터는 밖으로 가져올 수 없습니다

안심존에서 최종적으로 반출 가능한 것은 기본적으로

① 소스코드
② AI 모델 파일

입니다. CSV, NPY, 원본 데이터, 사용자 데이터 등이 포함된 데이터 파일은 반출할 수 없습니다. 이미지·영상·음성·압축파일 역시 반출 불가입니다.

성능 결과도 제한이 있습니다.

PDF에서는 AI 모델 성능 그래프 이미지는 ‘간단한 선 그래프’ 정도만 반출 가능하고, 심의 기준에 맞지 않으면 반려될 수 있다고 명시하고 있습니다.

그래서 예를 들어 이런 걸 밖으로 가져가는 것은 조심해야 합니다.

test_result.csv        ❌
patients.csv           ❌
shap_values.npy        ❌
processed_data.pkl     ❌
patient_examples.xlsx  ❌
MRI 이미지             ❌

train.py               ✅ 심의 후
preprocess.py          ✅ 심의 후
model.pkl              ✅ 심의 후
model.pt               ✅ 심의 후
model.h5               ✅ 심의 후

단, 실제 승인 여부는 반출심의 결과가 최종 기준입니다.

9. 그래서 모델을 만들 때 ‘모델 파일 자체에 데이터가 들어가지 않게’ 해야 합니다

이건 아주 중요합니다.

예를 들어 모델을 저장할 때

{
    "model": model,
    "training_data": X_train,
    "labels": y_train
}

처럼 학습데이터까지 같이 pickle로 저장하면 반출 문제가 생길 가능성이 큽니다.

대신:

{
    "model": model,
    "feature_names": feature_names,
    "threshold": threshold,
    "model_version": "1.0"
}

처럼 추론에 필요한 정보만 저장하는 구조가 좋습니다.

가능하면 최종 반출용 모델은 학습용 프로젝트와 따로 만들어 두는 게 좋습니다.

training workspace
       │
       ↓
final_model
       │
       ├─ model.pkl
       ├─ inference.py
       ├─ preprocessing.py
       └─ config.json

그리고 model.pkl에 환자별 데이터나 학습 샘플이 포함되지 않았는지 확인합니다.

10. 반출 일정도 미리 잡아야 합니다

이 부분을 놓치면 한 달 작업을 하고도 모델을 못 가져오는 상황이 생길 수 있습니다.

반출하려는 파일은 Jupyter의

nasw/download

폴더에 넣어야 합니다.

그리고 자원 종료일 기준 최소 영업일 3일 전까지 반출 신청해야 합니다.

반출 심의 자체가 영업일 기준 약 2~3일 걸리며, 중간 반출 2회 포함 최대 3회까지 반출할 수 있습니다.

따라서 30일을 꽉 채워 모델 개발하면 안 되고 저는 대략 이렇게 운영하는 걸 권합니다.
