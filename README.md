# AI Hub + 공공데이터포털 통합 데이터 카탈로그

AI Hub 데이터셋(975건)과 공공데이터포털 파일데이터(약 84,000건)를 한 화면에서 검색·비교하고,
**Gemini에게 목적을 설명하면 필요한 데이터를 추천받는** 로컬 대시보드입니다.

> 공개 사이트(Cloudflare Pages)로 올리는 방법은 [docs/Cloudflare-Pages-배포.md](docs/Cloudflare-Pages-배포.md) 를 보세요.
> 파이썬 서버 없이 정적 샤드 + Pages Functions 로 같은 화면이 동작하고, AI 추천은 관리자가 켜고 끕니다.

## 실행 — `실행.bat` 하나면 됩니다

더블클릭하면 메뉴가 뜹니다. 번호만 고르면 나머지는 알아서 진행됩니다.

```text
[1] 배포하기      스냅샷 → 정적 빌드 → GitHub → Cloudflare Pages   (약 5분)
[2] 전체 실행     위 과정에 데이터 수집까지 전부                    (몇 시간)
[3] 데이터 수집만 AI Hub + 공공데이터포털 새로 받기
[4] 로컬 대시보드 http://localhost:8765
[5] 현황 보기     수집이 어디까지 됐는지
[6] Pages 배포만  이미 빌드된 site/ 를 그대로 올리기
[7] GitHub 업로드만
```

명령줄에서 바로 부를 수도 있습니다(자동화·예약 실행용).

```bash
python run.py publish     # 스냅샷 → 빌드 → GitHub → Pages
python run.py all         # 수집까지 전부
python run.py crawl       # 수집만
python run.py serve       # 로컬 대시보드
python run.py status      # 현황
```

> 처음 clone 했다면 `실행.bat` → `[4] 로컬 대시보드` 만 고르면 됩니다.
> `data/catalog.db` 가 없으면 깃에 포함된 스냅샷에서 **자동으로 복원**한 뒤 서버가 뜹니다.
>
> `실행.bat` 안에는 영문만 들어 있습니다. cmd.exe 가 한글이 든 배치 파일을 잘못 읽고
> 중간에 멈추는 문제가 있어, 한글 안내는 전부 `run.py` 가 출력합니다.

## 1. 화면 구성

### 통합 / AI Hub / 공공데이터포털 탭
- **분야 필터**: 네모 칩을 눌러 **여러 개 동시 선택**(공공행정 + 보건의료 …). `전체`로 해제.
- **제공 방식 컬럼**: 데이터를 실제로 받을 수 있는지 표에서 바로 구분합니다.

  | 배지 | 뜻 |
  |---|---|
  | `↓ 다운로드` | AI Hub: 신청 후 내려받기 가능(866건) · 공공데이터: 포털에서 파일 다운로드 |
  | `↓ 다운로드 (승인)` | AI Hub 개별 승인 절차가 필요한 데이터 |
  | `🔒 안심존` | AI Hub 안심존 데이터(109건). 이용신청 후 **열람만** 가능, 다운로드 불가 |
  | `↗ 기관 제공` | 공공데이터: 제공기관 자체 사이트에서 다운로드 |
  | `↗ 오프라인` | 전자기록매체로만 제공 |

  AI Hub 행에는 용량(예: 228 GB)도 함께 표시됩니다.
- 검색어/형식/미리보기 필터, 열 정렬, 페이지네이션(25·50·100·200)은 모두 **서버에서** 처리하므로
  8만 건이어도 브라우저가 느려지지 않습니다.
- ★ 를 누르면 **내 데이터**에 담기고 `data/my_datasets.json` 에 저장됩니다.

### 상세 패널 — 출처별로 탭 구성이 다릅니다
| 출처 | 탭 |
|---|---|
| **AI Hub** | 개요(소개·구축목적·제공정보·기본정보·구축업체·AI 성능) / 메타데이터 구조표 / 데이터 통계 / 어노테이션·데이터 구조 / 활용 AI 모델 / 데이터 성능 / 저작도구 / 구축 업체 / 변경 이력 |
| **공공데이터포털** | 개요(설명·핵심정보) / 파일데이터 정보(기본·제공정보 전체) / 데이터 항목(컬럼) / 미리보기(행 샘플) |

### ✦ AI 추천 탭
화면 하단의 **"어떤 주제에 필요한 데이터가 필요하신가요?"** 바를 누르면 열립니다.

1. 목적을 문장으로 입력 — 예) *"청소년 우울증 조기선별 모델을 만들고 싶습니다"*
2. Gemini가 **검색 키워드**를 뽑고 → 로컬 카탈로그 84,933건에서 후보 60건을 찾아 →
   목적에 맞는 데이터만 골라 이유·활용법을 정리합니다. (지어낸 데이터가 섞이지 않도록
   **카탈로그에 실제 존재하는 uid만** 통과시킵니다.)
   - 후보를 넘길 때 **실제 데이터 항목(컬럼 이름)** 을 함께 전달합니다. 그래서 데이터명이
     그럴듯해도 필요한 값이 항목에 없으면 걸러지고, 추천의 `활용 항목`은 **추정이 아니라
     실제 컬럼명**입니다. 데이터끼리 결합할 **연결키**(공통 항목)도 함께 제시합니다.
   - 항목 색인은 공공데이터 미리보기 헤더와 AI Hub 메타데이터 구조표에서 만들며
     현재 **61,661건**(공공 60,874 · AI Hub 787)을 담고 있습니다. 검색어도 항목명에 매칭됩니다.

**AI 추천이 질문을 이해하는 방식 (4단계)**

1. **질문 분석** — Gemini가 질문을 읽고 `핵심 개념`(없으면 쓸모없는 것 3~6개), `확장어`(동의어·표기변형·기관명 10~16개),
   `지역`(제주·부산 등), `원하는 형태`(이미지·텍스트·음성·정형), `AI 학습 목적 여부`를 뽑습니다.
   같은 질문은 결과를 캐시해 재검색이 흔들리지 않습니다(`data/keyword_cache.json`).
2. **AI Hub 의미 선별** — AI 학습 목적이거나 이미지·음성 등 비정형 데이터를 원하면, AI Hub 975건의 제목 전체(약 10K 토큰)를
   Gemini에게 보여 **의미로** 골라냅니다. `텍스트 윤리검증 데이터`(욕설 필터), `노지 작물 질병 진단 이미지`(병해충 진단)처럼
   데이터명이 질문과 다른 낱말로 지어진 경우를 문자열 검색으로는 절대 못 찾기 때문입니다. 뽑힌 이유도 함께 기록합니다.
3. **후보 검색** — FTS5 trigram 색인으로 한국어 부분일치 검색(3글자 이상 1ms 이하). 점수 규칙:
   - 핵심 개념 일치는 확장어의 **2배**, 핵심을 하나도 안 맞춘 데이터는 제외(후보가 20개 미만이면 확장어 2개 이상 맞춘 것으로 보충)
   - 확장어는 많이 맞춰도 **상한(30점)** — 발생현황 통계가 관련어를 10개씩 맞춰 이미지 데이터를 밀어내던 문제 방지
   - **지역**이 지정되면 그 지역 데이터 +15, 다른 지역 접두어 데이터 −6 (제주 질문에 제주 데이터만 60건 확보)
   - **AI 학습 목적**이면 AI Hub ×1.2, 원하는 형태(이미지 등)와 맞으면 ×1.5; 정형 통계만 있는 데이터는 ×0.6
   - 의미 선별로 뽑힌 데이터는 +40 하고 반드시 후보에 포함
   - 같은 데이터의 **지역별 복제본은 묶음당 3건**만 (`OO시_주요관광지 입장객` 15개가 자리를 독식하지 않게)
   - 흔한 낱말은 IDF로 가중치를 낮추고, 키워드마다 상위 30건은 반드시 확보
4. **최종 선별** - 후보 120건에 실제 컬럼명·설명·제공방식과 함께 `요구 요약`(지역·형태·목적·핵심 개념)과
   의미 선별의 근거(★ 전문가 검토)를 넘겨 Gemini가 활용 흐름을 씁니다.
   **역할(핵심/보조/참고)은 Gemini가 직접 라벨을 고르지 않습니다.** 라벨을 고르게 했더니 같은 질문에도
   매번 뒤바뀌어(3회 반복 시 데이터의 42~62%가 역할 변경), 아래처럼 바꿨습니다.
   - Gemini는 **세 값 중 하나만** 답합니다 - `90`(빼면 목적을 이룰 수 없다) / `60`(빼도 동작하지만 품질이 떨어진다) / `30`(직접 안 쓰고 참고용).
     "몇 점을 줄까"가 아니라 "이 데이터를 빼면 무엇이 불가능해지는가" 하나만 묻습니다.
   - 점수 → 역할 변환은 **코드에 고정된 임계값**(70/40)이 합니다. 사다리 값이 임계값에서 떨어져 있어 판단이 흔들려도 역할이 잘 안 바뀝니다.
   - 사다리 밖 숫자(67 등)는 가장 가까운 단계로 스냅하고, 같은 점수면 **검색 단계의 결정론적 순위**로 정렬합니다.
   - 같은 질문·같은 모델의 결과는 통째로 캐시합니다(로컬 `data/reco_cache.json`, 배포 Cloudflare KV 30일).
     같은 질문은 **언제나 같은 답**이 나오고 재질문은 즉시·무료입니다. `refresh: true` 로 새로 받을 수 있습니다.
   - **쓸 수 있는 데이터는 빠짐없이 담습니다(최대 25개).** 후보를 60건에서 120건으로 늘렸는데,
     60위와 61위의 점수가 사실상 같아(80.5 vs 80.5) 필요한 데이터가 잘려 나가고 있었습니다.
     대신 지역·학교명만 다른 같은 종류의 데이터는 묶어서 3~5건까지만 후보에 올립니다.
     추천 건수는 평균 5.5건 → **13.8건** 이 되었습니다.
   - 컬럼 정보가 없다는 이유만으로 제외하지 않도록 규칙을 둡니다.

검증(6개 주제): 정답 데이터가 후보 1~2위에 오르고 최종 핵심으로 선택됨 — 예) 병해충 진단 → `시설/노지 작물 질병 진단 이미지` 1·2위,
욕설 필터 → `텍스트 윤리검증 데이터` 1위, 제주 혼잡도 → 제주 데이터 60건 전부, 독거노인 → `독거노인 돌봄용 위험감지 데이터`.
검색은 0.1~5초, 새 질문의 전체 추천은 12~55초, 비용은 질문당 약 ₩15~40입니다(의미 선별 단계가 붙으면 +₩10 안팎).
같은 질문을 다시 하면 캐시에서 1~2초 만에 같은 결과가 나오고 비용은 0원입니다.

역할 안정성 검증(3개 주제 × 3회 반복): 캐시 전 42~62% -> **캐시 후 0%**. 상위 데이터는 캐시 없이도 항상 같은 역할입니다.

### AI 설정 (오른쪽 위 ⚙)
- **Gemini API 키**: [Google AI Studio](https://aistudio.google.com/apikey)에서 발급.
  키를 입력하고 포커스를 옮기면 바로 저장되고 모델 목록을 불러옵니다.
- **모델**: 계정에서 실제 쓸 수 있는 모델을 **API에서 그대로 가져와** 세대별로 묶어 보여줍니다.
  - 정렬은 버전 숫자를 비교해 **항상 최신 세대가 맨 위**입니다(모델명을 코드에 박아두지 않으므로
    구글이 새 세대를 내면 새로고침만 해도 바로 위에 뜹니다).
  - `항상 최신 (별칭)` 그룹의 `gemini-flash-latest` / `gemini-pro-latest` 는 구글이 최신 모델로
    자동 연결해 주는 별칭이라 손대지 않아도 계속 최신을 씁니다. (새 설치 기본값 = `gemini-flash-latest`)
  - 이미지·음악·음성·임베딩·로보틱스 모델은 JSON 텍스트 출력을 못 하므로 목록에서 제외합니다.
  - 도움말의 **"최신 모델(...)로 맞추기"** 를 누르면 한 번에 최신으로 바뀝니다.
  - 목록에 없는 신규 모델은 **"목록에 없는 모델 직접 입력"** 으로 ID를 적어 바로 쓸 수 있습니다.
- 키는 **이 PC의 `data/settings.json` 에만** 저장되고 브라우저로 다시 내려보내지 않으며
  `.gitignore` 로 깃에서 제외됩니다.

## 2. 깃 업로드 방식 (용량 문제 해결)

`data/catalog.db` 는 원본 HTML·미리보기 본문까지 담고 있어 **400MB 이상**이라 그대로 올릴 수 없습니다
(GitHub 파일 상한 100MB). 그래서 **스냅샷 방식**을 씁니다.

| | 크기 | 깃 |
|---|---|---|
| `data/catalog.db` | 약 400MB | ❌ 제외 |
| `raw/` (원본 HTML 캐시) | 수백 MB | ❌ 제외 |
| `data/settings.json` (API 키) | – | ❌ 제외 |
| **`data/snapshot/items-*.jsonl.gz`** | **약 123MB (4파트)** | ✅ 커밋 |
| `data/datasets.json`, `data/details/` | 약 38MB | ✅ 커밋 |

```bash
python snapshot.py export    # catalog.db  -> data/snapshot/*.jsonl.gz (파트당 38MB 이하로 분할)
python snapshot.py restore   # 스냅샷      -> catalog.db 재생성
python snapshot.py info      # 현재 상태 확인
```

- 스냅샷에는 목록·분야·기관·형식·설명·상세정보와 **미리보기 전체(컬럼명 + 샘플 행 200만 행)** 가
  모두 들어갑니다. 즉 `catalog.db` 를 그대로 되살릴 수 있습니다. 제외되는 것은 재수집 가능한
  원본 HTML 캐시(`raw/`)뿐입니다.
- 복원 시 데이터 항목 색인과 검색 색인(FTS)이 자동으로 다시 만들어집니다(복원 약 90초).
- 데이터를 갱신한 뒤에는 `실행.bat` → `[1] 배포하기` 를 고르면 스냅샷·빌드·커밋·배포가 한 번에 끝납니다.

### 수집이 끝나면 자동으로 깃에 올리기
```bash
python publish_when_done.py              # 수집 완료를 기다렸다가 스냅샷 생성 + 커밋 + 푸시
python publish_when_done.py --now        # 기다리지 않고 지금 바로
python publish_when_done.py --no-push    # 커밋까지만
```
완료 판정은 ① 미리보기 대기(pending) 0건, 또는 ② 수집기 프로세스가 없고 20분간 진행이 없을 때입니다.
5분마다 진행률·속도·예상 시간을 출력합니다.

> 스냅샷은 압축 파일이라 **커밋할 때마다 저장소 기록이 약 30MB씩 늘어납니다.**
> 수집이 끝난 뒤 한 번만 올리는 것을 권장합니다.

## 3. 파일 구성

| 경로 | 설명 |
|---|---|
| `catalog.html` | 통합 대시보드(목록·상세·내 데이터·AI 추천·설정) |

## 4. 수집기 사용법

```bash
pip install requests beautifulsoup4

# AI Hub
python crawl_aihub.py                # 전체 수집(캐시 사용) + JSON 생성
python crawl_aihub.py --refresh      # 목록 갱신 + 새 항목만 수집
python crawl_aihub.py --parse        # 재수집 없이 다시 파싱

# 공공데이터포털
python crawl_data_go_kr.py --list --catalog --details      # 목록/상세정보 갱신
python crawl_data_go_kr.py --missing-previews --previews   # 미리보기 확인 + 이어받기
python crawl_data_go_kr.py --status                        # 수집 현황
python crawl_data_go_kr.py --details --previews --id 15118669
```

건별 상태를 SQLite에 저장하므로 중간에 중단해도 같은 명령으로 이어서 수집합니다.

## 참고
- AI Hub 사이트 표시 977건 중 975건 수집: 페이지 이동 중 최신순 정렬이 바뀌어 2건이 중복 노출된 것으로 실제 누락은 아닙니다.
- AI Hub 파일 목록(개별 파일명·용량)은 로그인 후 AJAX로만 제공되어 수집 대상에서 제외했습니다.
